# Spiceinit-pin receipt 20261114 -- `tt_25c_3.30v`, all five families (#338)

- **What this is**: the bounded fleet verification the pinned run-directory
  `.spiceinit` (#338) needs: a one-corner-per-family `klt sim` **deck-mode run
  on the 2am EDA batch fleet** with the staged `.spiceinit` as a deck input,
  checking two claims -- that the pin survives deck transport (the worker's
  engine stdout carries the pinned mode), and that the pinned run reproduces
  the committed 2026-08 record values for the same corner. Graded by
  `sim/lib/deck_adapter.py reduce`, same as `20261114-tt_25c_3.30v.md`
  (the unpinned parity receipt for this corner; it lands with #230's
  migration PR #339, which is why it is referenced by name and not linked
  here -- this receipt's layout mirrors it).
- **What this is not**: a new characterization claim. No record under
  `sim/*/records/` was minted, edited or superseded, and nothing here changes a
  recorded measurement. It is evidence about the **generator and its
  environment**: with the staged `.spiceinit`, the fleet runs the decks under
  the same ngspice state the committed corpus ran under.
- **Corner**: `tt_25c_3.30v` (process `tt`, 25 C, VDD 3.30 V) -- the nominal
  point of the ratified 27-corner matrix, and the corner where
  `20261114-tt_25c_3.30v.md` measured the
  unpinned-mode residual this pin exists to remove.

## What was pinned, and why

Single source of truth: `SPICEINIT_TEXT` in `sim/lib/deck_adapter.py`
(sha256 `e1a1d1767609427159244035b5a761f1bf43df653e7cfd0cd40a6f762829dffc`),
staged as a deck input (`decks[].inputs[]`, object form
`{"path": "units/<id>/.spiceinit", "name": ".spiceinit"}`) so it lands at the
dotfile name in the run directory. The reason each line is pinned, and the
mechanism choice, are documented in `sim/README.md` "The pinned ngspice
environment"; the short form:

- `set ngbehavior=hsa` -- the mode the committed corpus ran under (`hs a`) and
  the mode the gf180mcu model decks are written against.
- `set num_threads=1` -- fleet workers rely on per-worker single-threaded
  ngspice; a run-directory `.spiceinit` would otherwise drop the host setting.
- `set wnflag=1` -- not implied by `hsa`; inert while every device is `nf=1`,
  pinned so a future multi-finger device cannot silently change bin selection.

`options.ngspice_init` is deliberately **not** set in any request this repo
emits: on the deck-list path `klt sim` accepts the option and silently drops
it (`2AMLogic/klayout-tools#5738`), so using it would record a pinned mode
that was never in force. The staged input is transported
(`sim_decks.py` forwards `inputs[]` into the worker request where the option
allowlist drops `ngspice_init`), which is exactly what the fleet leg below
confirms.

## How it was run

```bash
# one bounded request per family, built by the adapter. `build` on this
# branch stages all 27 corners (corner selection is #339's `--corner`,
# pending); the submitted request is that build's output with `decks`
# filtered to the single tt_25c_3.30v unit -- no other field touched
# (the adapter block still says corner_count: 27, by design: the filter
# is documented here, not smuggled into the artifact).
for fam in read-snm hold-snm write-margin read-access write-access; do
  python3 sim/lib/deck_adapter.py build "$fam" \
    --stage-dir /tmp/spiceinit-pin-338/stage/"$fam" \
    --request-out /tmp/spiceinit-pin-338/stage/"$fam"/request.json
done

# one batch job per family, submitted as a set (never a local grid)
klt sim --batch-set /tmp/spiceinit-pin-338/stage/*/request.json \
  --max-in-flight 5 --wait-for-capacity 600 \
  -o /tmp/spiceinit-pin-338/out \
  --report-out /tmp/spiceinit-pin-338/batch-set-envelope.json --format json

# caller-owned grading (on this branch, without #339's --request, the
# reducer expects all 27 corners, so the 26 unsubmitted corners grade OPEN
# by design; the graded corner itself is what this receipt reads)
python3 sim/lib/deck_adapter.py reduce <fam> <report.json> --json-out <reduced.json>
```

Every reduce graded the submitted corner `recorded` (`reduced.json` in each
family directory). `recorded` is the reducer's own grading of
`RESULT:`/`RESULT-ERROR:` lines (and `snm_extract.py` for the DC-sweep
families), not the engine's exit status: exit 0 is never read as a
measurement pass.

## Local controls (the pin, not the host, sets the mode)

Run before spending fleet capacity, one single-unit deck request each, local
backend, this dispatch host (whose `~/.spiceinit` sets `wnflag`/`num_threads`
but no compatibility mode):

| Request | Staged `.spiceinit`? | Engine stdout |
|---|---|---|
| positive control (`read-snm`, one unit) | yes | `Note: Compatibility modes selected: hs a` |
| negative control (same deck, `inputs` removed) | no | `Note: No compatibility mode selected!` |

Same deck bytes, same host, same ngspice: the only difference is the staged
input, so the mode difference is attributable to the pin alone. Without the
negative control the test could not distinguish a working pin from a host
that happened to agree.

### What the pin bought, in microvolts

The unpinned fleet run
(`20261114-tt_25c_3.30v.md`) matched the
committed records only to within 2-14 uV on the two SNM families (<= 7 ppm),
with the residual attributed to the compatibility-mode difference
(`No compatibility mode selected!` on the worker vs `hs a` in the committed
logs). With the mode pinned, that residual is **zero at this corner** -- the
pre-#213 cross-check reproduces every committed SNM digit exactly, and the
three `RESULT:`-emitting families remain exact. The environmental difference
#338 opened with is closed deliberately, not resolved by accident.

For completeness, this run's current-extractor values (`reduced.json`,
post-#213) are `read_snm_v = 0.289120` and `hold_snm_v = 0.942795` -- the
same values the unpinned run reported under the current extractor, i.e. the
extractor change, not the mode, is what moves those from the committed
numbers.

## Limits

- **One corner, one sample per family.** `tt_25c_3.30v` only, matching the
  bounded-run convention. The other 26 ratified corners now run under the
  same staged `.spiceinit` by construction (one source of truth, staged by
  the same code on every path, byte-identity asserted by
  `sim/lib/test_deck_adapter.py`), but they have not been re-measured -- and
  must not be: re-grading them is a separate decision with its own receipts.
- **`wnflag`/`num_threads` are pinned but unmeasured.** Every device in this
  repo is `nf=1`, so `wnflag` cannot change bin selection today; the
  `pre213` cross-check matching exactly is consistent with that, but the pin
  of those two lines is justified by the host-dependence argument in
  `sim/README.md`, not by a differential measurement.
- **The worker's PDK revision is not verifiable from the report** (same as
  the parity receipt): `PDK_ROOT=/opt/pdk`, stamp unavailable. The exact
  agreement with the committed records is the only evidence the worker
  resolved equivalent models.
- **The Monte Carlo adapter has no live run.** `mc-build` stages the same
  pinned file per unit (the offline tests assert it), but no MC campaign has
  been submitted anywhere; that remains open work under #230.
- **`--corner` filtering is manual on this branch.** The submitted requests
  are `build`'s full output with `decks` filtered to one unit; when #339's
  `--corner` lands, the filter step disappears and the receipt's command
  block simplifies.
