# Deck-mode parity receipt 20261115 -- the full 27-corner grid, all five families

- **What this is**: the full-grid measurement-parity run for the staged `klt sim`
  deck-mode migration (#230) -- blocker 2 of `sim/README.md` "Staged migration to
  `klt sim` deck mode", extended from the one-corner receipt of 2026-11-14 to
  **every corner of the ratified 27-point matrix** (`spec/sram.md` "Corner set"),
  for all five characterization families: 5 x 27 = 135 deck-mode units in one
  `klt sim --batch-set`, graded by `sim/lib/deck_adapter.py reduce` and compared
  to the committed records by `sim/lib/parity_compare.py`.
- **What this is not**: a new characterization claim. No record under
  `sim/*/records/` was minted, edited or superseded, and nothing here changes a
  recorded measurement. It is evidence about the **generator** (does deck-mode
  transport reproduce the launcher's numbers at every corner?), not about the cell.
- **Authorization**: the 2026-11-14 operator ruling on #230 (bounded live parity
  runs authorized; "The Curator may also schedule the follow-up corners that
  parity needs without coming back to the operator") and the 2026-11-15 curated
  increment scheduling exactly this grid. The hand-rolled launchers stay in
  place; cutover is not part of this run.
- **Result**: **parity holds for all five families at all 27 corners.** The three
  `RESULT:`-emitting families reproduce the committed record value **exactly** at
  every corner (108/108 record metrics, zero delta). The two SNM families match
  through the documented pre-#213 crosscheck with a worst recorded-metric delta of
  **1 uV (read SNM)** and **7 uV (hold SNM)** against the 30 uV gate; no metric on
  any corner exceeded 30 uV. Zero `OPEN` units.

## How it was run

```bash
# one full-grid request per family (no --corner: the all-27 default)
for fam in read-snm hold-snm write-margin read-access write-access; do
  python3 sim/lib/deck_adapter.py build "$fam" \
    --stage-dir <scratch>/stage/"$fam" \
    --request-out <scratch>/stage/"$fam"/request.json
done

# a one-corner write-margin probe first (this host has no PDK, so the probe went
# to the batch fleet rather than --backend local; job klt-sim-85a43133d08f,
# graded recorded with the exact committed value before the grid spent capacity)
klt sim <scratch>/stage/probe-write-margin/request.json \
  --backend batch --wait-for-capacity 600 -o <scratch>/probe-out \
  --report-out <scratch>/probe-report.json --format json

# one batch-set submit for all five members (never a local grid)
klt sim --batch-set <scratch>/stage/*/request.json \
  --max-in-flight 5 --wait-for-capacity 600 \
  -o <scratch>/out \
  --report-out <scratch>/batch-set-envelope.json --format json

# caller-owned grading, coverage pinned to each request's own corner list
python3 sim/lib/deck_adapter.py reduce <family> <out>/request-<i>/report.json \
  --request <scratch>/stage/<family>/request.json \
  --outdir <out>/request-<i> --json-out <family>-reduced.json

# mechanical comparison against the committed records (re-runnable)
python3 sim/lib/parity_compare.py <family> <receipt>/<family>/reduced.json \
  --request <receipt>/<family>/request.json \
  [--sweep-dir <receipt>/<family> --pre213 <(git show e140796^:sim/lib/snm_extract.py)>]
```

Every reduce returned `overall: recorded` with `coverage_errors: []` -- the
reducer's own grading of `RESULT:`/`RESULT-ERROR:` lines (`snm_extract.py` for the
DC-sweep families), never the engine's exit status. All five batch-set members
reported `status: pass` (5 submitted, 0 refused);
unit exit codes were 0, which alone proves nothing -- the grading and comparison
below are the evidence.

### Why the residual microvolts (unchanged from 2026-11-14)

The committed 2026-08 corner logs carry `Note: Compatibility modes selected: hs a`;
this run's worker stdout carries `Note: No compatibility mode selected!` (verified
on this run's units, not assumed from last time). ngspice's compatibility mode
comes from the executing host's `.spiceinit`, which deck mode does not transport.
Across all 27 corners it is worth at most ~20 uV, and only on the two geometric
SNM metrics; the three families with their own `RESULT:` lines show it as nothing
at all -- now demonstrated at every corner, not just the nominal one. Pinning the
mode in the request is #338 / PR #346 and is not part of this receipt.

## Limits

- **Deterministic matrix only.** This receipt covers the 27-corner corner grid.
  It says nothing about the Monte Carlo adapter (`mc-build`/`mc-reduce`), which
  still has no live run of any kind -- that is the next increment.
- **The worker's PDK revision is not verifiable from the report** (unchanged from
  2026-11-14): the worker reports `PDK_ROOT=/opt/pdk` with no PDK stamp, so
  `pdk_stamp_comparison` is `not_comparable` and `models_lib_comparison` is
  `not_comparable`. The measurement agreement above is the only evidence the
  workers resolved equivalent models.
- **Spot instances, a different ngspice build.** `ngspice 47` (2026-11-13) versus
  whatever the 2026-08 record hosts ran; the microvolt residuals above are its
  measured size across the whole matrix.
- **Not a cutover.** `sim/lib/run_corner_sweep.sh` and the `run_mc_campaign.py`
  process pool are untouched and remain the documented procedure. Retiring them
  is blocker 3 and needs the MC receipt plus its own decision.
